## Problem / outcome

The Office Pack and Warehouse Pack meshes are generated by Python/Blender
scripts in the sibling repos
(`../unity-project/office-pack`, `../unity-project/warehouse-pack`) and
exported as FBX into each project's Unity package
(`*.Unity/Packages/**/Meshes/*.fbx`). Right now the website only links out to
the marketplaces — there is no way to actually look at the models.

Add a page where a visitor can browse the **Free-tier** meshes from these
packs, filter the list down, and inspect any single mesh in an interactive 3D
scene.

**Scope: Free-tier meshes only.** Only the assets in each repo's `kit.json`
`tiers.free.assets` list are published here (~15–30 meshes per pack). Paid-tier
meshes are deliberately excluded — a browser viewer has to ship the real
geometry to the client to render it (devtools / `THREE.GLTFExporter` can
recover it), and these are low-poly hard-surface meshes where the topology
essentially *is* the product, so there is no fidelity level that showcases well
while being worthless to copy. Free meshes have no such concern. This is
settled — see Notes.

Done looks like:

### Route & page

- New top-level `/meshes` route, added to the main nav (`nav-links.ts`) and
  also linked from the Assets page.
- `three` is loaded via dynamic `import()` only on this route (same pattern as
  `<HeroCanvas>` / ADR-0004); nothing runs during the vite-ssg prerender;
  WebGL failure falls back to the static thumbnail.

### Grid

- One **flat grid** of every Free-tier mesh from **both packs merged**, sorted
  pack-then-alpha. Free tier is ~25 meshes total (10 Office + 15 Warehouse).
- Each card is a focusable `<button>` (`role="button"` semantics): static
  preview PNG + mesh name + pack badge + triangle count. No live 3D on cards.
- Two filters only: a **segmented pack control** (`All · Office Pack ·
  Warehouse Pack`, single-select) and a **text search on name**. No category
  filter and no tier filter in v1 — see Notes. Filter state reflected in the
  URL query so a filtered view is shareable.
- Standard empty state when the search matches nothing.

### Selecting a mesh → the viewer

- Selecting a card opens an **in-page modal** (`role="dialog"`, `aria-modal`,
  labelled by the mesh name). Focus is trapped; Escape closes; on close, focus
  returns to the originating card. Fade + slight scale ~150ms; instant under
  `prefers-reduced-motion`. Full-screen sheet below 640px.
- The open mesh is **deep-linkable** via `?mesh=<slug>` alongside the filter
  query params. Loading a URL with `?mesh=` opens the viewer on that mesh.
  Prerender still only emits `/meshes`.
- Browser **Back closes the viewer in one step**: prev/next navigation uses
  history `replace` (not push), while still updating `?mesh=` so the URL stays
  copy-shareable.
- **Prev/next** walk the current filtered list (arrows on-screen + keyboard
  ←/→, keyboard-reachable, no wrap). The list is **frozen at open time**; the
  filter controls are inert while the modal is open.
- **Deep-link vs. filter conflict:** if a URL carries filters *and* a `?mesh=`
  that isn't in that filtered set, the mesh wins — filters are discarded for
  the session and prev/next walks the full merged list positioned at that mesh.
  Never land someone on a link that shows nothing.

### The viewer itself

- **Orbit and zoom only, no pan** (`OrbitControls`, `enablePan = false`,
  target locked to mesh centre).
- **Very slow auto-spin** — a gentle turntable, ~2–4°/s (`autoRotate = true`,
  low `autoRotateSpeed`). Pauses while dragging, resumes after a short idle.
  **Off entirely under `prefers-reduced-motion`.**
- Default camera framed to the mesh bounds; lighting rig roughly matching each
  pack's `DESIGN.md` §8.
- One persistent `WebGLRenderer` for the page lifetime (created on first open,
  torn down on route leave). Switching mesh disposes the old geometry and adds
  the next node from the already-loaded pack `.glb` — no context churn on
  prev/next.
- **Chrome:** header row = mesh name + position indicator (`2 / 24`) + close
  (✕). Elsewhere: triangle count (always shown), pack label, a
  **wireframe toggle that persists across prev/next**, and one prominent
  **marketplace CTA** for that mesh's pack ("Get the Warehouse Pack →") — the
  gallery's job is to funnel interest to the packs.
- **Loading / failure:** modal opens instantly on the preview PNG + a spinner,
  swaps to canvas on first frame. WebGL unavailable → keep the PNG, small
  "3D preview unavailable in this browser" note, prev/next still work. `.glb`
  fetch failure → PNG + "Couldn't load the model" + Retry.
- No "download" affordance anywhere. Not a protection measure (these are the
  free meshes, and the `.glb` is served to the browser regardless) — this is a
  gallery, not a distribution channel; the marketplace links are how you get
  the files.

### Data & pipeline

- `src/data/meshes.ts` (or a generated manifest) describing each mesh:
  **`slug`** (flat, globally unique across packs — e.g. `warehouse-sink`,
  `office-sink`, since the two packs share many mesh names; used as the
  manifest key, the `?mesh=` value, the DOM id, and the `.glb` node lookup),
  display name, pack, model reference (which `.glb` + node name), thumbnail,
  triangle count. No `category` field — omitted until a category feature
  actually needs it (see Notes).
- Both packs' `.glb` (one bundled file each, <300 KB total) are fetched on
  page load, after the route's `three` chunk resolves — so the first selection
  and every prev/next is instant.
- A documented, repeatable step in each pack repo that emits the web `.glb`
  and refreshes this repo's manifest — run manually when the packs change
  (see Notes for the format).

## Notes

The load-bearing decisions and their rationale are recorded in
[ADR-0007](../adr/0007-mesh-gallery-viewer.md): Free-tier only, `.glb` + Meshopt
bundled per pack, modal viewer with one persistent WebGL context, flat globally
unique slugs, no category filter in v1. The notes below expand on the
implementation.

- **Licensing / what to publish — decided: Free-tier only.** The gallery
  publishes only `kit.json` `tiers.free.assets` from each pack. Rationale:
  a static site must send the real `.glb` to every visitor's browser to
  render it, so anything shown is effectively extractable (devtools,
  `THREE.GLTFExporter`); and for low-poly hard-surface meshes, decimating the
  paid assets enough to devalue a rip also visibly wrecks the silhouettes and
  facet shading that a single-object viewer puts under a magnifying glass —
  there's no fidelity level that both showcases well and protects. Free meshes
  carry no such risk. If the paid packs ever warrant a showcase, that's a
  separate decision (e.g. a fixed-angle turntable video, not a live viewer).
  Recorded in ADR-0007.
- **Asset format.** Decided: add a **web export target to each pack repo**
  that emits **`.glb` (glTF 2.0 binary) with Meshopt compression +
  quantization** (`gltfpack -cc`). glTF is three.js's native format; `.glb`
  is a single self-contained file; Meshopt gives Draco-class size with a
  ~10 KB shared decoder and much faster decode, and `gltfpack` also does the
  vertex quantization that matters most here.
  These meshes compress extremely well: low-poly, hard-surface, **no textures
  or UVs** — just the flat `kit.json` material palette (metallic/roughness
  factors, base-colour hex). So the export should:
  - keep positions + normals (needed for the lit viewer), quantize hard
    (`-vp 12 -vn 8`), drop UVs / tangents / vertex colours / morph targets /
    animations entirely;
  - keep materials as PBR **factors only** (no image maps, no KTX2 needed);
  - expect **~2–10 KB per prop**. With only the Free tier in scope
    (~15–30 meshes per pack), a whole pack is well under **300 KB**.
  Given that, **bundle each pack into one `.glb`** with named nodes and load
  it once, rather than one request per mesh. Pipeline: Blender
  `export_scene.gltf(format='GLB')` → `gltfpack -cc` in each repo's existing
  script flow; no `fbx2gltf` / Draco needed.
- **Hosting.** Two small `.glb` files — commit directly to `public/` (or
  `assets/`). No CDN, no separate assets branch, nowhere near GitHub Pages
  limits.
- **Where the conversion runs.** The `.glb` is produced **in each pack repo**
  as a normal build output (a new export target restricted to the Free-tier
  asset list) and copied into this repo alongside the manifest, mirroring how
  `assets.ts` content is sourced manually today. CI here has no access to the
  pack repos, so the committed `.glb` + manifest are an artifact, not a build
  step.
- **No category filter in v1.** The Free tier is ~25 meshes total; the pack
  segmented control plus name search already make that navigable, and a
  category axis over 25 items either gives ~4 vague buckets or ~8 buckets of
  ~3. So v1 ships pack + search only, the manifest carries no `category`
  field, and no shared vocabulary is defined. If the catalogue ever grows
  (more Free meshes, or a decision to reverse ADR-0007 and bring the paid
  packs to the site), revisit then — a taxonomy is reconstructable from the
  `.glb` node names and each pack's `previews/` layout (Warehouse's Blender
  sources are already foldered: `dock/`, `cold-storage/`, `restroom/`, …).
- **Component split.** Likely `<MeshGallery>` (grid + filters + URL sync),
  `<MeshViewerDialog>` (the modal shell, focus trap, prev/next, chrome,
  loading/error states, `?mesh=` sync), and `<MeshViewer>` (the renderer:
  `OrbitControls` + `GLTFLoader` from `three/examples`, `enablePan = false`,
  low `autoRotateSpeed`, persistent `WebGLRenderer`). The persistent renderer
  lives at the dialog level so prev/next doesn't recreate it. Single-mesh
  viewer for v1; a "pose several meshes in one scene" mode is a later issue.
- **Interaction spec** for the grid, selection, deep-linking, and the viewer
  is settled — see the "Selecting a mesh" and "The viewer itself" sections
  above; the load-bearing choices and rationale are in ADR-0007.
- Thumbnails: ~15–30 per pack, small enough to drop straight into
  `assets/images/` and go through the existing `thumbnails.ts` resolver.
  Source them from each pack's `previews/*.png` (crop/resize as needed); flag
  any Free-tier mesh with no preview render.
